# Phase 06 별도 작성 holdout의 출처와 경계

작성일: 2026-10-22. 기준 저장소 commit: `780891f6c147cfd3c1a3b0d065792776aaa525f3`.

## 작성자의 정보와 분리 수준

이 자료는 구현 담당자와 다른 **동일 모델의 에이전트**가 작성했다. 작성자는
`HANDOFF.md`, `docs/RESEARCH_LOG.md`, `docs/MATHEMATICS.md`,
`docs/NEXT_EXPERIMENT.md`를 그 순서로 읽었다. 이후 기존 자료의 스키마와 의미를
확인하려고 `research/phase05/fixtures.py` 전체 및 `research/phase05/study.py`의
처음 145줄을 읽었다.

작성자는 공개 H6 가설, 후보 문법, 연구 대상인 의미 family를 전달받았다.
또한 full-history fork로 부모 대화에 나온 scoped-TOP 설계 설명을 상속받았다.
**따라서 방법 자체를 모르는 블라인드 작성자가 아니며 외부 독립 평가도 아니다.**
새 선택기 소스, 새 평가기 소스, 새 선택기의 예측이나 성능 결과는 열지 않았고
선택기 또는 기존 언어 파서를 실행하지 않았다. 데이터 생성을 위해 새 알고리즘에
맞춰 문장을 통과시키거나 실패시키는 튜닝도 하지 않았다.

구현 담당자는 이 파일 및 holdout 내용을 새 알고리즘 동결 전에는 읽지 않기로
했다. 작성자는 파일 경로, 분모, SHA-256, 제한 사항만 전달했다. 이 과정에서
얻는 분리는 **구현·출력 미열람 상태의 작성 분리**이며, 동일 모델·공유 설계·
공유 합성 언어로 인한 상관성은 남는다.

두 split은 같은 초기값·gold 전이·질문을 두 표면 표현으로 쓴 **짝지어진 조건**이다.
384개의 독립 대화 표본으로 세지 않는다. `heldout_controlled`라는 이름도 모든
문장이 파서에 지원된다는 뜻은 아니다. 부정·복합 변경·미지원 질문처럼 지원 문법의
경계를 시험하는 사례가 의도적으로 포함된다.

family는 장소만 늦게 변경, 다른 모임만 변경, 시간 변경 뒤 상대 이동, 나중에
덮어쓴 미해석 변경, 중간값 복사, 두 대상 중 하나만 변경, 인용, 한 원문의 복합
변경, 부정, 늦은 정정, 미지원 질문, 긴 후행 변경이다. 각 이력의 처음 네 기록은
두 모임의 시간·장소를 모두 초기화한다. 마지막 family의 후행 길이는 4/8/12/16개이며
무관한 긴 문장 padding 없이 실제 장소 변경만 반복한다. 이 family는 인위적인
반복 구조이므로 pooled 바이트 수치와 함께 family별 결과를 보는 것이 적절하다.

## 라벨의 의미와 작성 원칙

모든 기록은 제한된 **계획 상태**의 권위 있는 입력 또는 명시적 비행동이라는
실험 가정을 따른다. 실행 성공, 캘린더 반영, 실제 사실성의 증거로 사용하지 않는다.
시간은 일반 정수이며 24시간 범위·달력 제약을 적용하지 않는다.

라벨은 템플릿의 의도된 의미에서 먼저 작성한 전이다. 값이 결정되지 않은 문장을
임의의 단일 값으로 라벨링하지 않았다. 예를 들어 “장소만 다시 정해줘”는 목적지가
정해지지 않았으므로 이번 자료에서 사용하지 않았다. 두 모임 중 정확히 하나를
선택하는 표현만 `maybe_set`으로 두 결과를 함께 보존했다.

| `gold.kind` | 의미 |
|---|---|
| `set` | 특정 필드를 명시된 값으로 지정 |
| `add` | 해당 시점의 시간에 정수 이동량을 더함 |
| `copy` | 해당 시점의 다른 필드 값을 복사 |
| `maybe_set` | 주어진 두 대상 중 정확히 하나에 지정 적용 |
| `noop` | 명시적인 인용·부정·비행동으로 상태 유지 |
| `sequence` | 한 원문에 담긴 `events`를 순서대로 모두 적용 |

`sequence`는 부모 연구자가 평가기 지원에 동의한 뒤 복합 변경에 사용했다.
이는 하나의 원문에 두 변경이 있을 때 하나만 정답으로 기록하는 오류를 피하기
위한 평가용 표현이다. 원문 선택기는 이 gold event를 입력받아서는 안 된다.
명시된 복합 변경은 장소와 시간을 함께 지정한다. 인용과 부정은 실제 변경
이력을 취소하는 모호한 소급 의미 대신, 해당 문장 자체가 비행동임을 명확히 썼다.

`public`에는 `records`, `entities`, `snapshot`만 들어간다. 각 원문 기록에는
`seq`, 무작위 `id`, `text`만 있으며 family, split, gold, 필수 근거, 최종 답을
넣지 않았다. 평가기가 호출 시 질문을 추가할 수 있지만 다른 필드를 넘기면 안 된다.
record ID는 선택·정답을 암호화하지 않고 고정 seed로 생성한다.

## 재현과 실행한 검사

```bash
python research/phase06/holdout_builder.py --check
```

처음 생성하려면 `--check` 없이 실행한다. 이미 다른 내용의 파일이 존재하면
덮어쓰기를 거절한다. 생성기는 Python 표준 라이브러리만 사용하고 기존 또는
새 선택기·언어 파서·평가기 모듈을 import하지 않는다.

실제로 실행한 검사는 96이력/384질문의 분모, 쌍별 gold와 질문의 동일성, 초기
네 필드의 지정, 연속 순서, ID 유일성, 공개 입력 키 경계, gold 연산 및 대상
스키마, snapshot hash, 재생성 바이트 동일성이다. **자연어 의미를 외부 사람이
검증한 검사나 선택기 성능 측정은 실행하지 않았다.** 작성자가 템플릿과 gold의
대응을 검토했지만 이는 저자 라벨이며 독립 전문가 판정이 아니다.

초기 생성 및 재생성 확인 결과:

| 파일 | SHA-256 |
|---|---|
| `holdout_builder.py` | `61a116677fc4f80f0e5139c41fb032338b2d20a3fc9560c7386a639dc184c916` |
| `data/holdout.json` | `ee2640474780954514f3018e971701c49e273bf6b4e6f5d156bcd2428035a830` |

데이터 크기는 269,310 bytes다. 이 바이트 크기는 데이터 파일 크기이며 프롬프트
절감률·LLM 토큰·실행 비용이 아니다. 이후 라벨 오류를 발견하면 원래 자료와
결과를 유지하고 별도 정정으로 남겨야 한다.

## 해석 제한

- 새 이름·값·표현·연산 조합의 합성 holdout이며 자연 발생 대화가 아니다.
- 대상 질문이 시간 또는 시간·장소의 현재 상태에 치우친다. 관계의 정서적 의미,
  권한, 미완료 요청의 실제 생명주기, 실행 증거의 진위는 평가하지 않는다.
- 미지원 질문은 전체 변경 과정과 실제 캘린더 반영을 묻는다. 그 질문을 현재
  계획 값으로 대신 답하는 것은 정상 인증으로 평가해서는 안 된다.
- gold는 의미상 명확하게 만들었지만 일부 표현의 자연스러움·범용성은 낮다.
  새 문법으로 성능이 좋아져도 자유 한국어 이해의 일반화를 주장할 수 없다.
- 이 자료를 한 번 보고 선택기나 라벨을 조정하면 이후 결과는 사후 분석이다.
  원래 고정 알고리즘의 결과를 보존해야 한다.
