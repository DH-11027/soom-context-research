### 기존 연구에 대한 정정·새 발견

1. **기존 평가기의 빈 인증 공백을 실제 재현했다.** `phase05/study.py::evaluate`는
   반환된 prediction 키만 순회한다. `certified_model`인데 `prediction={}`인
   mutant도 false certification과 containment 위반이 모두 false로 통과했다.

   소급해서 오류 결과로 바꾸지도 않았다. [최소 재현](BASELINE_AUDIT.md).

   `{(0,0),(1,1)}`, `c=1`일 때 `{(0,1),(1,0)}`를 내면 각 필드 marginal은 같지만
   공동 답은 다르다. 분기·제어·alias 의존성을 빠뜨린 일반화는 성립하지 않는다.
   기존 product domain의 한계 자체는 이전 문서에도 명시되어 있었다.
3. **내부 보존과 reader가 검증할 수 있는 충분 근거는 다르다.** 현재 digest와
   선택 원문만으로 생략 사건의 의미 계약을 독립 검증할 수 없다. 이번 증명은
   선택기 내부의 보존이며 Phase04의 `Sufficient(E_prompt,q)`를 최종 프롬프트에
   대해 새로 증명한 것이 아니다. trace는 진단 자료이고 출력 바이트에 포함하지 않는다.

기존 핵심 구현과 제한된 수학 설명 사이의 중대한 불일치는 추가로 찾지 못했다.

## 이번 가설과 계약

### 선택한 하나의 병목

모르는 문장 하나가 모든 필드를 바꿀 수 있다고 처리되어 질문과 무관한 불확실성까지
전파되는 문제다. 더 강한 조합 최적화보다 **안전한 영향 범위를 얻는 비용과 범위**를
연구했다. 제안된 `may_write / must_overwrite / may_read` 전체를 구현하지 않고,
증명 가정이 더 작은 `may_write` 상한만 시험했다.

- **H6-S:** 올바른 상한 W를 얻으면 원문의 정확한 새 값을 몰라도 질문의 답 포함을
  보존하면서 더 많은 질문을 인증하고 더 짧은 선택을 만들 수 있다.
- **H6-C:** 그 절감이 계약 추출·추가 탐색 비용까지 상쇄한다.

실행 전 계획은 [PROTOCOL.md](PROTOCOL.md). H6-S의 조건부 수학과 H6-C의 경험적
비용 가설을 분리했다. 비용 가설이 실패해도 결과를 바꾸지 않았다.

### 입력·출력·수학적 보존

입력은 원문의 순서/opaque ID/text, 공개 엔터티 목록, 질문, snapshot이다.
선택기는 gold state/AST/family/split을 받지 않는다. `oracle_scoped`에만 별도
인자로 gold may-write를 준다. 정답 값이나 참조 AST 전체를 주지는 않는다.

필드 집합 U, 실제 사건 F, 추상 상태 a에 대해 다음 조건을 요구한다.

\[
\forall s,\ t\in F(s),\ x\notin W:\quad t_x=s_x.
\]

W 안의 값을 전부 TOP으로 보내고 나머지를 유지하는 추상 변환을 쓴다.

\[
H_W(a)_x=\begin{cases}\top_x&x\in W\\a_x&x\notin W\end{cases},
\qquad F(\gamma(a))\subseteq\gamma(H_W(a)).
\]

사건 뒤 필요한 필드가 D이면 역방향 요구는 `D \\ W`다. 관련된 W가 없으면 사건을
생략하고, 관련되면 TOP을 남긴다. 이것은 실제 사건의 must-overwrite를 안다는
뜻이 아니다. **추상 결과를 TOP으로 넓혔으므로 그 좌표의 이전 값이 필요 없어졌다는
뜻**이다. 나머지 D는 계속 추적한다.

정확히 인식한 set/add/copy/maybe_set와 결합하면 전체 추상 실행과 선택 실행의
질문 좌표가 같고, 각 전이의 soundness 가정 아래 구체 답이 그 Cartesian 예측에
포함된다. 여러 필드의 실제 상관관계를 정확히 표현한다는 보장은 아니다.
자세한 증명·반례·복잡도는 [THEORY.md](THEORY.md)에 있다.

동결 후에는 [POSTFREEZE_LIMITS.md](POSTFREEZE_LIMITS.md)에 계약의 경계를
추가로 증명했다. 비어 있지 않은 Cartesian 상태에서 W 외의 제약을 모른다면
H_W는 모든 frame 전이에 안전한 변환 중 가장 정밀하다. 임의 관찰 q에 대한
일률적인 정확 생략은 q가 U∖W 좌표만으로 결정될 때에만 가능하다. 또한 원문과
양립하는 의미들이 여러 개라면 안전한 W는 그 모든 may-write의 합집합을 포함해야
한다. raw-only 정확 인증에는 최악 경우 N개 기록을 모두 읽어야 하는 간단한
하한도 있다. 이 사후 증명은 challenge의 0효과를 불가능성 결과로 바꾸지 않는다.
challenge는 현재 문법 coverage 실패이며, 그 자료에서 더 좋은 추출기의 개선
가능성은 남아 있다. 기존 동결 문서와 알고리즘을 고치지 않았다.

## 실제 결과

### 분모와 독립성

새 자료는 12 family × 4 매개변수 × 2 표현 조건 = **96이력/384질문**이다.
두 표현 조건은 같은 잠재 전이·질문을 공유하므로 서로 다른 잠재 프로그램은
48개다. 조건별 192질문 중 지원 질문 184개, 미지원 8개, gold singleton 168개,
gold상 모호한 질문 16개다. IID 표본이나 실제 대화 384개라고 부르지 않는다.

6개 비교군의 2,304개 출력은 짝지어진 반복 결과다. 기존 회귀 자료는 별도의
336이력/672질문이며 6개 방법의 4,032개 출력을 평가했다. 이 672질문은 새로운
독립 평가가 아니다. 개발 68질문은 결과 표의 새로운 평가 분모에 합치지 않았다.

### 답변 범위와 오류: 새 평가

`certified_model`은 제한된 계획 모형의 단일 값 판정이다. 아래 모두 원문 전용
분석기 또는 명시된 oracle 결과이며 실제 사실성/실행 성공의 인증이 아니다.

| 조건·방법 | 인증 / 192 | opaque fallback | 모호성 | 미지원 | 실제 전체 이력 출력 | 틀린 인증 / 인증 |
|---|---:|---:|---:|---:|---:|---:|
| 문법 근접 · frozen | 26 | 158 | 0 | 8 | 166 | 0/26 |
| 문법 근접 · text-scoped | **100** | **72** | 12 | 8 | **80** | **0/100** |
| 문법 근접 · oracle | 120 | 52 | 12 | 8 | 60 | 0/120 |
| 표현 변형 · frozen | 6 | 178 | 0 | 8 | 186 | 0/6 |
| 표현 변형 · text-scoped | **6** | **178** | 0 | 8 | **186** | **0/6** |
| 표현 변형 · oracle | 108 | 76 | 0 | 8 | 84 | 0/108 |

각 분석기/조건에서 containment 위반은 지원 질문 184개 중 0, 출력 schema 오류 0이다.
두 원문 조건을 합하면 새 text-scoped는 **106개를 인증했고 그중 오류 0**이다.
이를 전체 384개에 모두 답했다거나 실제 오류 확률이 0이라고 해석하면 안 된다.

gold상 단일 답을 갖는 지원 질문 168개 중 인증 비율은 문법 근접에서
15.48% → **59.52%**, 표현 변형에서는 3.57% → **3.57%**였다. 전체 192개 대비
인증 범위는 각각 13.54% → **52.08%**, 3.125% → **3.125%**다.

미지원 질문은 변경 과정과 실제 캘린더 반영이다. 현재 계획 값으로 대신 답하지 않고
전체 이력을 전달했다. `full_history` 방법은 모든 원문을 전달할 뿐 답을 생성하지
않으므로, 그 containment 0을 질문 응답 정확도로 집계하지 않는다.

| 전체 원문 출력 대비 감소 | 32.81% | 1.36% |
| 상세 파서 호출: frozen → text | 158 → **72** | 178 → **178** |
| cheap 파서 호출: frozen → text | 304 → **858** | 232 → **232** |
| 추가 scope 호출 | **310** | **178** |
| 동일 가중치 byte-work proxy: frozen → text | 267,407 → **280,758** | 297,685 → **315,417** |
| proxy 비용 변화 | **4.99% 증가** | **5.96% 증가** |

출력 감소 분모를 혼동하지 말아야 한다. 28.53%는 이미 줄인 frozen 출력에 대한
추가 감소이고, 32.81%는 전체 원문 출력에 대한 감소다.

문법 근접에서 86건의 축소 중 12건은 새 singleton이 아니라 모호성을 유지한
압축이었다. 이를 인증 증가에 합치지 않았다. 표현 변형에서는 계약이 한 번도
좁혀지지 않았다. 이 조건의 보존 검사 통과는 **새 최적화의 성공이 아니다**.

비용 벡터의 세부 값:

| 알고리즘 원문 처리량 | 문법 근접 frozen | 문법 근접 text | 표현 변형 frozen | 표현 변형 text |
|---|---:|---:|---:|---:|
| snapshot 직렬화/hash bytes | 129,408 | 129,408 | 138,036 | 138,036 |
| cheap 입력 bytes | 19,059 | 48,012 | 20,438 | 20,438 |
| scope 입력 bytes | 0 | 20,843 | 0 | 17,732 |
| detail 입력 bytes | 11,279 | 5,551 | 17,732 | 17,732 |
| 별도 reparse bytes | 0 | 0 | 0 | 0 |
| 추상 실행 단계 수 | 228 | 290 | 212 | 212 |

새 파이프라인에는 명시적 재파싱 단계가 없고 cache를 재사용한다. 그러나 같은
문장을 cheap → scope → detail로 여러 번 처리하는 비용은 각 항목에 이미 센다.
전체 hash를 읽으므로 전체 입력 I/O가 sublinear라는 주장은 없다.

proxy는 `output + hash + cheap + scope + detail + reparse bytes`다. 같은 byte에
같은 가중치를 준 작업량이며 CPU·실제 LLM 토큰·원화 비용의 합이 아니다. 추상
검증/집합 연산은 단계 수와 시간으로 따로 보고한다. oracle annotation 작성비는
측정하지 않았으므로 oracle의 proxy를 실제 전체 비용으로 비교하지 않는다.

문법 근접의 총 차이는 다음과 같다.

\[
\Delta P=-30{,}717_{output}+28{,}953_{cheap}
            +20{,}843_{scope}-5{,}728_{detail}=+13{,}351.
\]

출력과 원문 처리에 서로 다른 단가를 줄 경우 결론은 달라질 수 있다. 단순한
두 가중치 모형 `C=α·output+β·source_work`에서는 이 조건에서
`α/β > 44,068/30,717 ≈ 1.435`여야 양의 이득이다. 이것은 실비 추정이 아니라
관측된 작업량에 대한 손익분기 조건이다. 표현 변형에서는 출력 이득 0, 추가
scope 입력 17,732 bytes이므로 이 두 항만으로는 양의 비용 이득이 없다.

로컬 Python의 5회 반복, 순서 회전 후 전체 조건의 중앙 실행 시간:

| 조건 | full-history | frozen | global-control | text-scoped | text-eager |
|---|---:|---:|---:|---:|---:|
| 문법 근접 192질문 | 2.611 ms | 5.992 ms | 6.447 ms | 8.492 ms | 10.857 ms |
| 표현 변형 192질문 | 2.979 ms | 5.956 ms | 7.071 ms | 6.217 ms | 11.272 ms |
| 기존 회귀 672질문 | 14.598 ms | 27.021 ms | 29.011 ms | 29.963 ms | 94.888 ms |

검증·파싱·추론·렌더링을 포함한 계측된 로컬 실행이며 gold 평가기는 이 타이머
밖이다. 매우 짧은 합성 Python 실행이라 환경 잡음이 있고 실서비스 지연으로
일반화하지 않는다. 반복별 원자료는 `results/timing.json`에 있다. hash 바이트
계측은 실제 SHA용 직렬화에서 얻으며 추가 크기 계산용 중복 직렬화는 하지 않는다.

### 불리한 family 결과도 보존

`long_suffix` 문법 근접 조건은 출력이 **57.94% 감소**했지만 proxy가
**22.03% 증가**했다. 기존 방법은 마지막 미해석에서 빨리 중단하고 전체 이력을
반환한다. 새 방법은 많은 장소 변경을 확인하며 시간을 확정할 과거까지 더
탐색한다. 출력이 짧아지는 과정 자체가 공짜가 아니라는 직접적인 사례다.

복합 변경·부정은 좁은 범위로 단정하지 않고 전역 TOP을 유지했다. 결과가 없는
조건을 제거하거나 유리한 family만 평균내지 않았다. 전체 family 비교는 결과
JSON의 `families`에 있다.

- 범위 문법 6개 긍정 사례와 18개 인용/취소/복합 변경 부정 최소쌍 검사.

## 해석과 다음 차례

### 지지·기각·미확인

| 주장 | 판정 |
|---|---|
| 올바른 frame 상한이 주어진 scoped TOP의 답 포함 | 명시된 모형·가정 아래 증명 |
| W 외 정보가 없을 때 scoped TOP보다 더 정밀한 uniformly sound 변환 | nonempty Cartesian 모형에서는 불가능; 사후 최소성 증명 |
| 제한 문법에서 실제 더 작은 선택과 더 넓은 인증 | 새 문법 근접 합성 조건에서 지지 |
| 이번 원문 분석기의 표현 변형 일반화 | 새 challenge 조건에서 지지 안 됨: 추가 축소 0 |
| 같은 가중치 byte-work proxy의 전체 이득 | 새 두 조건 모두 지지 안 됨: 비용 증가 |
| 실제 LLM 토큰·금액·지연·응답 품질 개선 | 미측정, 판단 불가 |
| reader가 선택된 프롬프트만으로 생략 정당성 검증 | 미구현·미증명 |
| 실제 실행 증거·미완료 요청·관계·권한 보존 | 현재 상태 모형 밖, 검증하지 않음 |

주요 한계는 두 개다. 첫째, frame 상한을 안전하게 얻는 언어 분석이 좁은 문법을
벗어나면 작동하지 않았다. 둘째, 더 정밀한 답을 얻는 추가 탐색·검사 비용을
출력 감소와 분리해서 평가해야 한다. 더 좋은 조합 탐색을 붙여도 이 두 문제를
자동 해결하지 않는다.

동결 후 알고리즘·라벨·평가 조건 변경은 없다. 사후 보고서는 고정 결과를 해석하는
문서이며 새 독립 성능 결과가 아니다. reviewer가 추가로 발견한 사항은 별도
[POSTFREEZE_REVIEW.md](POSTFREEZE_REVIEW.md)로 남겼다. 별도 family 산식과 96개
이력의 최종 joint 상태가 모두 일치했고, 새 평가 원시 2,304행의 재집계도 요약과
일치했다. 원래 자료를 덮어쓰지 않았다. 이 사후 검토는 같은 모델의 별도
에이전트가 결과를 읽고 수행했으며 외부 블라인드 검증이 아니다.

### 실행하지 못한 항목

실제 LLM/API/토크나이저, 외부 인간 작성 대화와 독립 라벨링, 운영 SOOM,
권한·실제 실행·미완료 요청 생명주기, 실제 검색 서비스, 최신 archive head 연동,
reader 독립 verifier, 새 scoped 언어와 reducer 결합, 외부 OS/장치에서의
Phase06 재현을 실행하지 않았다. 비용 proxy로 이 항목을 대신했다고 주장하지 않는다.

### 다음 Codex가 먼저 재현하거나 반박할 부분

1. 위 명령으로 freeze와 5개 결정적 산출물이 그대로 일치하는지 확인한다.

5. 사후 최소성 정리의 nonempty/full-product 가정과 읽기 하한의 무료 전처리

   더 강한 최적성 주장으로 확대하지 않는다.

### 다음 한 가지 연구 제안

**H7: 비용과 보류를 명시한 원문 전용 영향 범위 추출기의 독립 검증.**

이번 challenge에서 text는 인증 6/192, gold scope를 받은 비교군은 108/192였다.
이 차이는 값을 더 잘 최적화하기 전에 원문에서 안전한 W를 얻는 단계가 남았다는
증거다. 다만 oracle는 최소 의미 footprint나 달성 가능한 최대 성능의 엄밀한
상한은 아니며 annotation 작성비도 빠져 있다.

다음 단계에서는 현재 선택기는 고정하고 **범위 추출기 하나만** 교체한다.
외부 작성자가 만든 새로운 복합 변경/인용/부정/참조 최소쌍에 field-level gold를
붙이고, 모델·프롬프트·보류 정책을 개발 자료에서 정한 뒤 평가 자료를 동결한다.
출력 W가 실제 may-write를 빠뜨리는 비율, 수락 범위, downstream false certification,
전체 fallback, 실제 추출·검증 토큰과 시간을 함께 측정한다. 불명확한 입력은
전역 W로 돌아가야 한다. 그 실험의 수락 오류율을 자유 자연어 전체의 soundness
보장으로 바꾸지 않는다. 이번 파일의 표현을 추가한 뒤 같은 challenge를 새
독립 성과로 보고하는 것은 그 연구를 대신하지 못한다.
