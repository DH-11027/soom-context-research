# 다음 연구 제안: Phase 06

상태: **미실행 제안**. 기존 결과에 추가 성과를 주장하지 않는다. 다른 연구자가 가설을 비판하고 수정할 수 있도록 비교 계약을 먼저 적었다.

## 관측된 병목

Phase 05 stress에서 lazy는 288질문 중 240개를 opaque fallback으로 돌렸고 36개만 singleton으로 판정했다. 모르는 문장 하나를 모든 필드의 잠재 변경으로 처리하기 때문이다. 확정 사건 뒤에 긴 비행동 문장이 오면 상세 파싱을 거의 전부 해야 했다. reducer는 기존 corpus에서 0건을 더 줄이고 추가 파싱 비용만 만들었다.

따라서 우선순위는 더 강한 조합 탐색이 아니라 **안전하게 좁힐 수 있는 의미 영향 범위**다.

## 가설 H6

문장의 의미를 완전히 해석하기 전에 필드별 영향 계약을 얻을 수 있다면, 전역 TOP보다 적은 비용으로 같은 답 포함 관계를 유지할 수 있다.

- `may_write`: 바뀔 수 있는 필드의 상한.
- `must_overwrite`: 이전 값과 독립적으로 확실히 새 값이 지정되는 필드. 단순 may-write와 구분한다.
- `may_read`: 출력 필드에 영향을 주는 이전 필드의 상한.
- 출처 위치, 인용·가정·명령 여부, 검증되지 않은 부분을 함께 기록한다.

후보 변환은 “반드시 덮어쓰는 필드의 이전 의존성을 제거하고, 필요한 출력에 영향을 줄 수 있는 입력을 추가”하는 형태다. 실제 문장이 계약 밖의 필드를 변경할 수 있다면 unsound하므로 **계약 추출의 soundness가 핵심**이다. 엔터티 이름이 없다는 이유만으로 다른 필드에 영향이 없다고 확정해서는 안 된다.

## 순서와 비교군

1. 작은 typed 연산 언어에서 계약과 역방향 변환을 정의하고 반례를 찾는다. alias, copy, weak update, overwrite, 읽기 장벽을 포함한다.
2. gold AST로 정확한 footprint를 준 oracle ablation을 따로 실행해 최대 가능한 이득을 측정한다. 이것을 원문 분석 성능으로 보고하지 않는다.
3. 원문만 받는 계약 추출기를 별도로 만든다. 확인할 수 없는 표현은 전역 TOP으로 돌아간다. 새로운 문법을 추가할 때마다 긍정·부정 최소쌍을 작성한다.
4. frozen Phase 05 lazy, oracle footprint, text-only footprint, full-history를 비교한다. 상쇄 reducer는 독립 on/off ablation으로 둔다.
5. 의미 정확성 확인 뒤에만 cache 재사용이나 실제 토크나이저·모델 실험을 검토한다. 미실행 비용을 측정한 것처럼 적지 않는다.

## 평가 데이터와 누출 방지

기존 corpus는 회귀 검사다. 새 개선을 주장할 평가 데이터는 따로 둔다. 가능하면 방법을 모르는 작성자/평가자가 생성하고 사전 작성한 판정 기준으로 라벨링한다. 독립 작성이 불가능하면 같은 저자라는 한계를 그대로 보고한다.

현재 관측한 문제를 겨냥해 모호한 지시, 늦은 정정, 인용된 옛 보고, 장소만의 변경, 상대 시간 이동, 다른 엔터티의 중간 복사, 복합 변경을 넣는다. 실제로 문제를 보인 조건부터 확장하고 모든 상상 가능한 언어 현상을 미리 구현하려 하지 않는다.

평가기에만 gold state·필수 근거·family를 제공한다. 선택기는 seq·opaque ID·text·명시된 공개 메타데이터만 받는다. ID 치환 검사를 유지한다. 계획 상태와 실행 사실을 한 라벨로 합치지 않는다. 현재 값과 변경 과정 질문도 따로 평가한다.

## 실행 전에 고정할 판정 기준

| 항목 | 요구되는 증거 |
|---|---|
| 의미 보존 | 구체 실행 투영과의 비교; false certification과 answer containment 위반을 별도 보고 |
| 비공허성 | 새 계약이 실제 사용되고 더 작아지는 사례가 존재; 전부 fallback한 결과를 개선으로 부르지 않음 |
| 비용 | 출력·계약 추출·재파싱·해시·검증 비용을 분리; byte proxy와 token 측정을 구분 |
| 보수성 비용 | coverage·ambiguity·opaque·unsupported 비율을 함께 보고 |
| 새 모형의 장벽 | 중간 read/copy를 넘어 제거하지 않는 최소 반례 |
| 회귀 | 기존 672질문과 revision02 대수적 suite의 적용 가능한 비교 |
| 주장 범위 | oracle 결과, text-only 결과, 사후 재평가, 새 평가를 분리 |

단일 언어 해석 반례에서 false certification이 생기면 해당 보장의 주장을 철회하고 최소 재현 사례를 남긴다. 의미가 보존되어도 전체 비용이 늘면 실용적 개선은 실패다. 더 많은 fallback으로 오류를 줄인 경우에는 그 비용을 정면으로 보고한다.

## 대안 가설

H6가 자연어에서 안전하게 성립하지 않으면 일단 범위를 유지해도 좋다. 다음 후보는 (a) 동일 문장의 파싱 cache를 질문 간 재사용하는 비용 연구, (b) 답 포함 관계를 유지하는 작은 relational domain, (c) “현재 상태 / 과정 / 원문”의 질문 계약을 먼저 명확히 하는 선택적 응답이다. 각 방향은 별도 실험으로 분리하고 여러 개선을 한꺼번에 섞어 원인을 흐리지 않는다.

결과를 [반환 양식](RETURN_TEMPLATE.md)에 맞춰 돌려주면 다음 Codex가 독립 재현과 비판부터 이어갈 수 있다.
